FAQ

Questions about app plans

How does the customer pay?

The customer confirms the plan with one SMS (a QR code on desktop). Nothing is charged at that moment — all purchases in the period are collected onto a single bill that is settled later.

Which e-mail should be used?

The one the customer uses in your app. It becomes part of the payment reference (plan_<tier>_<hash>), so your backend can match a resolved commitment to the right app account.

What is an activation code?

A short code linked to the e-mail. It is the fallback when the purchase happened on the web but the app is installed separately: the customer enters the code in the app to switch the plan on. In production the code is issued by your backend, not derived in the browser.

Can I sell a single feature instead of a plan?

Yes. The same data-gvm-* flow sells one-off features and add-ons; every purchase in a period lands on the same bill. This page just shows the plan variant.

Is this a real charge?

No. The demo runs on the QA environment (data-gvm-env="qa", tenant wdft_showcase_qa) and the activation code is generated in the browser.
